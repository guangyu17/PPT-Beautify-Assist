# 全套风格与版式逻辑先行

模式 1/3 在任何 生图通道 付费样张生成前执行；模式 2 只记录原稿的逐页风格，不擅自统一原本不同的页面。
不要先做一张漂亮封面再猜其他页面怎么排。统一是明确的设计规则与页面角色，不是每页强塞同一构图。

## 先盘点全部页，再做样张

1. 模式 1 提取所有页、实际页数、顺序、隐藏页和画幅，查看全套原稿缩略图及必要单页；
   每页记录文字密度、图表/图片需求和内容层级。默认页数和顺序原样保留，无法读取的页标明未知。
   模式 3 先确认完整页数和逐页标题/类型/内容提纲，不能只规划前两页。
2. 如果只有一张或几张截图，明确“当前仅有 N 页参考”，索取完整材料或用户给出的总页数/大纲。
   可以讨论风格、给出针对这些页的建议；没有全部内容就不能宣称已确认整套版式，更不能生成推测的其余页。
3. 在 `layouts/deck-style.json` 保存全套设计提案，并在聊天说明整体页数、版式家族、背景强度、字体配色
   与整图合成/分层选择。先取得用户对全套设计范围的确认，再生成风格样张；已有明确指令可直接记录为依据。
4. 提案需覆盖所有页，但此时只生成代表页：封面＋最复杂内容页，必要时额外选数据密集页。
   样张仍按原有预览门展示并等明确选择，再锁定整套风格开始生产。未选中的候选不能混进后续页。

## 全套设计提案内容

- 模式1视觉重设计/模式3先按 [设计brief](distinctive-design.md) 填写 `design_brief`：受众/观看场景、讲述目的、目标感受、视觉隐喻、构图/阅读路径、字体/色彩/图像角色、避免/保留项及样张与素材预算。
- `directions` 记录各方向的实质差异和取舍；已有方向或样张获批后写 `selected_direction`。这些是设计记录，不是组合器的新参数；模式2只记录原稿。
- `page_count`、完整 `page_ids` 和原文件/大纲依据；`status` 区分 proposed、scope_confirmed、samples_approved。
- `style_id`、画幅、主底色/正文色/点缀色、标题/正文/数据字体与字号阶梯、固定页边距/标题起点/页脚区。
- `visual_language`：背景题材、材质/笔触、冷暖、光向、边框与图标线条、阴影与雾化强度；
  `intensity` 可选简约、精致、华丽、沉浸式史诗。简约不会被背景参考图推翻。
- `layout_families`：封面、图左文右、文左图右、时间线、地图/数据、章节/结尾等实际需要的家族，
  每类的网格、阅读路径、标题区、主图/正文区、可变范围；不是每页换字体/配色或另起一种风格。
- `pages[]`：每页对应家族、密度、主视觉、文本 safe_zones、计划素材、强度例外及理由。
- `image_mode`：separate_layers 或 integrated_visual；若整图包含原前景，记录允许合并的对象和不能合并的对象。
- `generation_budget`：样张、最终资产和复用量；按资产独立性、通道能力和完整请求体测量决定调用方式，不设固定批量。不生成时明确记0；不是全套计划一次发给生图通道。

这是主代理需实际编写/执行的设计合同，并非现有 compose 会自动读取的字段。
每页布局 JSON 和 prompt 必须落实合同；每次调用 生图通道 带简短相同的风格锚描述与该页要求，
确需参考时使用统一样张的无字视觉/风格参考，不能每页重选一套互不关联参考图。

## 生产与检查

批次结束以拼图对照已批准样张：字体、页边距、标题层级、背景温度、纹理、边框、图标与阅读节奏。
局部 alpha/渐变角度可自调，但不可悄悄改变整套色调/字族或正文结构。全局设计变更需要回到样张确认，
并重新渲染所有受影响页面。局部修复不能通过删字、改页序或复制整页图片绕过内容与可编辑性要求。

## 组件合同

统一component_theme与逐页component_plan，定义面板材质、线/框、箭头、图标语义及复用、时间轴密度。按 [语义组件](semantic-components.md) 先验证关系再绘制，不凭风格创造原文没有的因果。
