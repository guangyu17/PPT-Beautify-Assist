# 背景定制、底色与花纹边框

适用：模式 1 美化已有 PPT，以及模式 3 已确认结构后的设计阶段。
不适用：模式 2 忠实还原；只有用户明确转入美化后才启用。此参考仅扩展设计决策，
生图通道 调用始终遵守 [背景提示词与分批规则](background-prompts.md)，不增加独立并发队列。

先完成 [全套设计合同](deck-style-contract.md)，确认所有页面的视觉家族与排版逻辑，再进入本页级选项。
逐页变化必须服从已批准合同，不是让每一页拥有一套独立风格。

## 1. 在设计方向阶段一次问清

看到页面含文字或图片时，可以结合材料这样问：

> 是否希望我结合每页文字主题和配图，定制各页背景？也可以告诉我喜欢的背景底色，以及画面想偏简约还是华丽。

该问题先于付费样张生成；用户已明确说“按内容逐页定制”或“简约蓝白底”等，就采用，不再重复问。
不需要为每一页问一遍，也不要在用户没回应时默认开启整套逐页定制。
用户希望代理自行选择时，可提出并记录推荐值，但不伪造用户确认，真实样张确认门仍保留。

向用户提供简短说明与底色色块/色名（自然语言即可，可用已有 visualize 预览承载）：

| 选择项 | 可以提供的选择 | 决策边界 |
|---|---|---|
| 背景方式 | 统一背景族 / 按每页内容定制 / 只定制封面和章节页 | 未明确同意逐页定制时用统一背景族，仍按页面角色安排留白 |
| 背景板底色 | 原主题色 / 配图协调色 / 用户指定色 / 2–3 组推荐色 | 主底色 + 文字色 + 点缀色一起看；不要只给十六进制色号 |
| 装饰程度 | 简约 / 精致点缀 / 华丽 / 沉浸式史诗 | 选择简约就不混入华丽候选；没有风格偏好先询问，不假定想华丽 |
| 花纹与边框 | 无 / 角部花纹 / 细边框 / 开放式边框 / 华丽完整框 | 随内容密度调整，完整框只在可读且用户接受时采用 |
| 原图融合方式 | 保留独立主体 / 原图与环境一体化 | 选择一体化前说明主体失去独立拖动能力，文字不合并 |
| 页间变化 | 相同纹样的变化 / 每页不同但同风格 | 固定配色、材质、线条语言；变化的是图案、角饰和摆放，而非每页换主题 |

可推荐主题相关的花纹：学术/科技的抽象几何、文化内容的纸纹与纹饰、自然主题的植物边饰、
庆典或作品展示的金属细纹/丝绸/雕花。都是可选设计建议，不是见到某主题就强制套用。
底色候选可如“深蓝＋香槟金”“暖白＋墨绿”“黑灰＋银色”；具体搭配服从原文与配图。

## 2. 简约风优先开关

识别到“简约、极简、干净、留白、不要花纹”等明确偏好时，设置：
`decoration_level=minimal`、`pattern=none`、`border=none`、`ornament_assets=[]`。
不新增主题插画、金属花纹、发光框、浮雕、颗粒堆叠或装饰性前景；也不为这些元素发 生图通道 请求。
仍可按每页内容密度/图片位置调整留白和底色，但“按内容定制”不等于“加花”。
默认不主动询问是否升级华丽，直接给简约范围内的色调与排版选择。
用户明确要求“简约但加极细边线”时，仅保留这个局部例外，并在样张中确认，不能扩展成整页花纹。

## 3. 先分析内容，再写每页视觉简报

只为用户同意定制的范围建立 `backgrounds/background-plan.json`：

- 全局：`background_strategy`、`decoration_level`、`palette`（底色、字色、点缀色）、
  `pattern_family`、`border_style`、`variation`、`scope`、`confirmed_preferences`、`approval_status`。
  偏好确认与最终样张确认分开记；尚未批准的样张阶段不可标记整套 approved。
- 每页：`page_id`、`page_role`、`content_theme`（从原文提炼的视觉主题）、`image_cues`
  （实际配图色调、主体位置、方向与质感）、`content_density`、`base_color`、`motif`、
  `border_variant`、`safe_zones`（统一为 0–1 的 x/y/w/h）、`reference_paths`、`asset_ids`。
- `safe_zones` 基于即将回填的实际版式，涵盖标题、正文、照片/图表及注释；留白不只用“中间空一点”描述。
  不把整页原文塞进图像提示词，避免模型生成字；用主题摘要与空间要求，正文仍原生逐字回填。
- 多图页可按主要配图提炼调色与纹理，不把所有图片作为参考一次上传。必要的参考原图与风格锚图
  参考数量按通道能力与完整请求体测量结果决定，派生副本另存，保留原始证据。
- 默认保留人物/产品/原图独立；若用户明确选择 [原图与环境一体化](epic-integrated-background.md)，可把
  已授权的书/人物/插画融入完整无字背景，并说明合并对象失去独立编辑能力。不再同时叠原主体造成双影。
  Logo、证据图形、数据与所有文字仍不生成改写。题材不改变事实、原文、顺序或页数。

计划只是后续执行的清单，不是脚本自动识别或自动批量调用的保证；现有 compose JSON 仍单独编制。

## 4. 底色、装饰与材质分层

纯色背景可原生可改，装饰图独立移动/替换。新设计的材质对话框/卡片按 [四档规则](beautify-tiers.md)
必须真实生图，不能用原生平板/模糊补丁冒充。无图像素材先说明未完成，不降级。
独立边框/角饰保持可调整；一整张不透明底图会遮住原生底色，不能改下面的颜色假称已换色。
严格品牌色尽量纯色底＋透明装饰；生成图像像素不保证精确HEX。完整边框校准画布，避免cover裁掉角饰。

## 5. 华丽而不干扰信息

封面与章节页可较丰富；文字密集页、表格页把图案退到角落或边缘，降低对比、减少密度。
可以每页使用不同角饰、局部纹样或开放边框，但让色调、材质和线宽语言一致，不机械地整套复制，
也不要每页完全不同。原文容纳不下时先减装饰，不能删字或把字号压到不可读。
生成后检查内容相关性、底色与配图协调、框线完整、透明开口、边缘裁切、正文可读性与跨页一致性。
独立装饰的完整图框可能触发重叠检查；仅在肉眼验证透明区域没有遮挡后，用明确的
`allow_overlap_with` 元素 ID 标记有意叠层，不能关闭全部重叠警告。

每次组合回填后还须执行 [视觉自检闭环](visual-review-loop.md)：重点检查内框与实际文字净空，
过小时先放大/移动可独立调整的框，不能只移到文字下面；修复四周裁切、明暗和透明叠层后再重渲染。

## 6. 用真实样张确认，而不是直接整套开工

提供 2–3 套用户允许范围内的方向；每套封面＋真实内容页，内容页优先选择文字较密或带主要配图的页，
让用户看到边框会不会挤正文。比较底色、同页花纹/边框变化及与图片的协调，不用空白背景代替排版预览。
用户确认方向、底色、装饰程度和定制范围后才排最终资产。若反馈“太花”，优先减图案与边框；
改成简约时取消尚未发出的装饰请求、保留旧结果，不删除原件，也不继续生成原华丽计划。

更新出图估算：预览资产 + 最终所需且不可复用的背景 + 单独配图/边框/角饰 − 可复用资产。
按唯一资产 ID 去重，不把一个多页复用边框重复计费；每个需要生成的独立装饰都计入原有分批队列，
批量、尺寸按通道能力与实际请求体决定；取消旧固定批量和固定小图限制，质量重试仍有界。


## 7. 更强场景与反复叠层

可按用户偏好从“装饰边框”升级到“完整环境”：旧书可融入地图桌面和灯光，远景引入山体/城堡纵深，
但只在题材合理且允许装饰性扩展时做。固定全套画风，正文所在区域保持低纹理，不让夸张背景淹没信息。
多层雾化/斜向渐隐/局部亮度按 [多层配方](layer-recipes.md) 逐层迭代，不每轮都重新生图。
