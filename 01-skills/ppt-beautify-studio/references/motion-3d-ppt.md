# PPT 动画、3D与着色器视觉适配

模式1/3且用户需要动态展示时读取，并按需加载 [UI/UX动态视觉子技能](../subskills/ui-ux-design/SKILL.md)。模式2静态原稿没有运动信息，不能推测原动画；局部静态修复不擅自加入动态。

## 先定交付与能力

记录目标PowerPoint版本/平台、放映设备、线上/离线、是否需PDF阅读版、媒体预算，以及动态元素是否必须作为原生对象编辑。用户已给出就复用，不重复询问。用户只需静态PPT时不增加动画任务。

本仓库现有`compose_slide.py`提供静态分层排版，没有动画时间轴、Morph、视频嵌入、原生3D或实时shader接口。给layout加`animation`、`shader`或`3d`字段不会产生这些效果。本文新增的是可执行的设计/选型/后处理指导，不是新的媒体渲染引擎。

若用户要求实际动态交付，先检查现有Office连接、可用原生自动化/编辑能力和媒体工具：可用时制作代表页，保存并在目标PowerPoint播放验证。需要工程扩展时明确新增实现范围，不把工具缺口当成完成。仅有静态组合器时可继续完成静态底稿/分镜并披露动态部分未实现，不交付名为“完整动画版”的静态文件。

## 效果路线

| 意图 | 首选方案 | 关键边界 |
|---|---|---|
| 逐步揭示逻辑、单对象强调 | PowerPoint原生出现/淡化/强调/路径等可用效果 | 使用原生编辑对象，按实际宿主能力制作并检查顺序 |
| 跨页保持产品/图形的空间连续 | 目标版本支持的Morph与共享对象 | 保留相同对象身份和有意义的起止姿态；不能靠额外复制内容页打乱原页数/顺序；图表不按普通对象假设可Morph |
| 产品旋转、模型空间展示 | 原生3D模型和宿主支持的3D动画 | 核验模型/贴图/许可、插入与播放能力；不承诺Office逐顶点编辑或支持网页shader |
| 流光、玻璃折射、液体、碎裂 | 生成或本地渲染的无字视频/序列，或受支持的原生效果 | 渲染成本与媒体预算另记；预渲染画面没有随用户任意视角/背景实时变化的能力 |
| PDF、邮件预览、无播放能力环境 | 明确关键帧/静态产品图＋原生文字 | 静态版独立讲清信息，不把PDF标成动画版 |

shader/Three.js画布不能通过截图变成PPT里的实时shader。可将授权制作的效果烘焙成无字素材，再与原生文字/图表组合；这样视频内部不可逐对象编辑，需要在样张阶段说明。若要求媒体主体也原生编辑，选择受支持模型/对象方案或报告冲突，而不是用视频替代后仍声称全编辑。

## 在设计合同中编排

在`layouts/deck-style.json`追加`motion_plan`设计记录（不是compose输入协议）：

- 每页/对象的effect_id与讲述目的、触发（点击/自动/与前一项同时等）、起止姿态、时长、延迟、缓动和顺序。
- 跨页共享对象对应关系与视觉锚点；不能改事实、删原文、擅自增页。装饰与主对象运动不要压过讲述节奏。
- implementation_route、实际工具及能力依据；planned/implemented/playback_verified等状态分开。写了分镜不等于动画已嵌入。
- 资产来源/路径/哈希、预算、媒体参数、文字safe_zones、静态poster帧或替代图；整套字体与留白继续受全套合同约束。
- 输入中断、快进/跳页、返回、重复播放、循环和声音策略；减少动态版可减少转场/相机运动并用静态姿态表达，不假定所有PPT宿主自动读取系统减少动态偏好。

分镜先做封面与复杂内容页的真实可播放样张；沿用现有样张门和档位/通道预算。若只有一个批准方向，直接扩展其动态样张，不重新强迫选风格。动态图像只呈现主视觉，正文、日期、数据、来源与图例仍为原生对象。

## 媒体与背景融合

先核验目标播放器的容器/编码/透明支持，不默认视频带alpha，也不把黑底误当透明。玻璃折射预渲染应配合最终背景；烘焙折射不能准确反映任意后加正文或改变后的背景。将这类画面放在合适视觉区，正文安全区保持清晰。

嵌入或链接策略由实际工具和交付场景决定；离线演示需验证换目录/另一台目标设备后的媒体可用性。保留来源文件、无字媒体、关键帧及布局，不把它们自动上传到代码仓库。

## 静态与动态分开验收

1. 静态：原文、页序、来源、独立对象和逐页实际渲染继续按 [视觉闭环](visual-review-loop.md) 核对。PNG/PDF不足以证明动画、3D或视频播放正确。
2. 动态：打开最终PPTX，在目标PowerPoint放映。记录宿主/版本、文件哈希、页号、实际录屏或关键时间点；检查点击顺序、时间关系、循环接缝、前进/后退/跳页返回、首帧poster、媒体缺失与离线播放。
3. 抽取起点、中段、终点和已知风险时刻，与动态样张对照；静帧只能证明这些时刻。实际播放看完整相关段，不能只看封面或一帧。
4. PDF/静态版使用事先选定的完整状态或关键帧，确认没有因逐步出现导致缺字。模式1保持页数时不自行拆成多帧多页；确需改变页数另按用户要求处理。文字仍可编辑的承诺针对PPTX，不把PDF当编辑格式。
5. `logs/visual-review.json`另记`motion_review`：当前PPTX/媒体哈希、目标播放器、场景、证据、检查结果和未验项。不能将planned或“Office打开正常”记为playback_verified。

主观审美先安排最多两轮，已无具体问题即停止，与原有每页最多4轮本地修复共用预算；播放/裁切/丢字缺陷仍按原有停止条件处理。无法通过时保留可阅读静态稿和真实缺口，不靠整页含字视频或截图伪造可编辑交付。
