# UI/UX 设计与动态视觉

先决定用户应理解什么、完成什么，再选择构图与动态媒介。沿用现有产品、品牌、技术栈和已批准方向；本技能可独立用于UI/UX，也作为PPT美化修改专家的内置设计子技能。调用子技能不会扩大主任务权限或替代PPT的内容/可编辑性合同。

## 1. 探索与定义

读取材料、参考与主任务。把“高级、酷、有个性”变为具体的阅读顺序、空间、材质、字体角色和互动感受；只询问影响决策的缺口。

未定方向时先列若干简短灵感供比较，不先全部实现，再收敛为2–3个在构图、信息组织、字体或媒介上实质不同的方向。每项说明适用理由和避免项。用户已定方向或只修一个问题时直接细化。遇到模板重复可选用本地真实随机源探索节奏，种子仅留本次任务，不显示到产品。

形成可执行brief：受众/主任务与观看设备、希望的感受、视觉隐喻及其用途、层级与阅读路径、字体/配色/图像角色、参考与反参考、保留项/避免项、最小代表页面或状态、素材/效果预算。明确哪些是假设，哪些已获批准。

## 2. 选择效果并实现代表状态

| 需求 | 起始路线 | 按需读取 |
|---|---|---|
| 静态信息与阅读层级 | 先做好字体、网格、对比、内容与图像裁切 | [评审与减法](references/review.md) |
| 点击反馈、展开、页面过渡、阅读引导 | 原生平台动画，先定义状态与时间关系 | [动画编排](references/motion.md) |
| 随输入改变的折射、形变、粒子或空间模型 | 检查现有渲染器，再选材质、shader或3D | [着色器与3D](references/shaders-3d.md) |
| 固定镜头的复杂物理运动或连续画面 | 可用预渲染视频/序列；不等同实时模拟 | [媒体与回退](references/motion.md) |
| PPT原生动画、跨页连续、3D或视频 | 先加载主技能的PPT动效适配；目标宿主决定可用路线 | 不把网页代码当PPT原生效果 |

每个动态效果都给出：目的、目标对象、触发方式、起止状态、时长/缓动/顺序、可中断与重播规则、触摸/键盘行为、静态/减少动态版本，以及验证方式。数值是本项目可调整的设计选择，不是通用质量标准。用户只要静态时不擅自加动效。

图像、材质、动效共同服务brief；保留核心文本和操作的可读性。先完成一个承载主任务的页面/状态或样张，不为展示技术堆满全套。需要外部生成能力时使用当前已授权的通道，缺工具就说明缺口；不默认新装引擎、接付费服务或沿用文章里的模型品牌。

## 3. 实际验证、评审和交付

先运行/播放，再捕获实际图像。静态截图检查构图；动态用起点、中段、终点、循环接缝和中断/返回证据，不能以一张截图证明动画正确。按 [评审](references/review.md) 检查主任务、视觉一致性及效果是否必要；有权限可用新上下文独立评审，否则明确自查。

先做最多两轮审美精修，每轮修1–3个主要问题；主任务故障、不可读或播放失败属于缺陷，不因审美轮数结束而通过。沿用宿主的费用/修复上限，不重置预算。移除不服务意图的装饰与说明，保留必要标签、状态、可访问名称与来源；PPT受保护内容以主技能为准。

交付选定brief、效果/状态清单、实际产物及证据路径，分别报告视觉、交互、性能、播放与静态回退的已验/未验状态。未执行的设备测试不写成通过。来源及公开阅读范围见 [来源说明](references/sources.md)。
