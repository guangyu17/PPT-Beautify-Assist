# 图像、着色器与3D的设计和实现

需要材质、粒子、形变、光效或空间交互时读取。先复用现有渲染栈、模型和材质；把效果设计成视觉角色，说明它怎样展示产品或组织信息。

## 选型

| 需求/条件 | 先尝试 | 取舍 |
|---|---|---|
| 卡片倾斜、轻层次、简单空间转场 | 原生变换/CSS透视 | 可表达2.5D深度，不是可任意观察的真实模型 |
| 有现成3D模型，旋转查看产品/空间 | 项目已有3D引擎与内置材质 | 摄像机、灯光、环境和几何通常比新增shader更先决定观感 |
| 内置材质表达不了的随输入形变、噪声或采样效果 | 自定义shader/节点材质 | 确认目标renderer、语言和项目版本；不要混用后端API |
| 固定镜头、无任意交互的复杂物理画面 | 预渲染视频/序列/关键帧 | 开销与兼容性需实测；不能称为实时模拟 |
| 静态交付、设备无GPU能力或预算不足 | 产品图/烘焙材质/原生排版 | 保留主任务与识别特征，记录视觉降级 |

Three.js官方ShaderMaterial为WebGLRenderer路线。使用WebGPU或别的引擎时，先核对已安装版本的对应材质方案；不把GLSL代码直接塞入不兼容的renderer，也不为一个效果默认换引擎。具体API随项目版本核验，本文不固定依赖版本。

## 一个效果从原型到落地

1. 用灰模/已有产品图确定构图、摄像机、焦点和主体尺寸；把正文、规格与购买等操作放在独立UI层，保持语义与可用交互。
2. 明确光向、冷暖、粗糙度、透明/厚度和环境反射的设计意图。玻璃先比较已有物理材质；自定义shader只负责缺失效果，不等于所有视觉都应手写shader。
3. shader原型分开控制几何/顶点形变与像素颜色/纹理采样。记录time、resolution、pointer、progress等实际需要的uniform含义、坐标范围和更新来源；未用的参数不堆进接口。尺寸变化时同步画布、摄像机和采样坐标，防止比例拉伸或指针位置错位。
4. 将图片作为材质/场景的一部分时检查色彩处理、纹理比例、UV、边缘、透明排序及混合结果。发光、折射和后处理在最终背景与真实文字上复查，避免高光吞字、穿帮或主体质感不一致。
5. 空间交互提供明确的旋转/复位/角度选择；拖动产品与滚动页面的手势归属需明确。hover是增强，触摸/键盘仍能到达必要操作。热点与可访问标签由UI提供，不依赖用户猜测3D画面。

## 3D动画的职责与时间

- 产品整体旋转/移动用对象或父级变换；模型自带骨骼/形变动画先检查真实clip、绑定与起止姿态；材质流光用材质参数或uniform变化。摄像机、几何、模型动画和材质各有职责，不把一切运动都塞进shader。
- 用统一时间源和实际秒数推进，避免按“每帧加固定角度”造成不同刷新率不同速度。Three.js的AnimationMixer可将真实AnimationClip映射为action，并用deltaTime（秒）更新；先确认加载结果是否存在所需clip，没有时不能假装播放成功。
- 为每个clip指定单次/循环/停末帧、速度、混合/切换和复位行为；多个层级同时旋转时检查局部与世界变换，避免镜头与主体意外叠加。拖动接管自动旋转时明确暂停/恢复所有权。
- 验证暂停恢复、任意时间跳转、循环接缝、姿态切换及卸载。释放mixer缓存前先停止相关action；还在被其他场景使用的模型/贴图继续由其所有者维护。PPT能否保留这些动画需另按PPT适配核验，不能从Web播放成功推断。

## 性能和生命周期

为目标设备约定可测的画面/加载预算，记录设备、浏览器、分辨率、DPR及实际帧耗时/流畅性。不要承诺未测的60fps。高DPR、全屏后处理、透明叠层和大纹理按实测取舍；DPR上限、粒子数量和采样精度是项目参数，不是普遍禁令。

静态模型视图按需渲染；持续动画只在需要时更新，离屏/隐藏时暂停并正确恢复，不重复创建渲染循环。组件卸载或替换资产时取消任务、监听器、控制器和本项目持有的资源；Three.js纹理、几何、材质等按所有权dispose，不能提前释放仍被其他视图共享的资源。

测试加载失败、shader编译/链接失败、WebGL上下文丢失与恢复路线；不能恢复时展示poster/静态图并保留主操作。记录真实GPU错误和恢复动作，不用“构建通过”证明GPU效果正确。若只改动设计方案，本轮记planned，不声称这些测试已运行。

起点/中段/终点、旋转背面、遮挡、触摸、窄屏、高DPR、减少动态和失败回退分别留证。效果应融入brief，不能为了显示shader或3D数量牺牲产品可读性。
