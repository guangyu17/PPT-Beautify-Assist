# 动画编排、视频与静态回退

有运动或交互状态变化时读取。先写“这段运动帮助用户理解什么”，再决定是否需要实现。导航、反馈、对象关系、产品展示可用不同节奏；装饰循环不能持续争夺正文和主操作的注意力。

## 编排与技术选择

- 原生控件的状态反馈优先沿用平台；网页的简单位移/缩放/淡入可从CSS或Web Animations API开始。需要统一时间轴或复杂手势时复用项目已有工具，不仅为一次过渡引入新库。
- 先画状态/关键帧表：对象、坐标/姿态、可见性、触发、持续时间、缓动、与其他对象的先后关系。先完成入场/强调/退出中的实际需要部分，不让每段文字都飞入。
- 用起止视觉状态表达因果或空间连续性。组内对象错峰只用于读序；避免无依据地把并列信息做成因果动画。动态正文仍需足够停留时间阅读。
- 对点击、悬停、拖动、滚动、按键分别定义触发；触摸不能依赖hover。规划快速连续输入、反向滚动、跳转、取消与重新进入：是从当前状态反转、重置还是播放到终点？避免多个并发时间轴争写同一属性。
- 原生媒体或动画实现需检查resize、焦点、遮挡、离开视口/页面后暂停与恢复。减少动态偏好改变时也更新行为；Web用prefers-reduced-motion或现有平台等效机制。静态内容与主操作不依赖动画播放成功。

## 预渲染与生成媒体

复杂液体、碎裂或固定镜头材质运动可选视频；需要用户任意转动、实时光照或改视角时不能以固定视频冒充真实3D。先检查可用素材和授权工具，明确生成数量、重试与预算；制作建议不等于调用服务授权。

- 固定主体/镜头/光线，写清首尾姿态、节奏与可循环条件。循环检查最后到第一帧，不只检查首尾静止图。
- 状态A→B→C的预渲染连续片段可用上一段最后一帧作下一段参考；仍逐段检查身份、镜头和接缝，不保证模型天然保持一致。滚动控制视频时测试首尾、随机跳转、快速反向及解码停顿。
- 需要透明媒体先核验容器、编码、播放器的alpha支持。简单背景可色键，复杂边缘需抠像；玻璃半透明、反光与头发边缘尤其需实际看底色变化。不能因模型说“透明背景”就记为透明视频。
- 折射预渲染可匹配目标背景色再合成；折射已烘焙，不能随任意实时背景准确变化。背景变更后重新看融合，必要时选实时材质或重新渲染。
- 保存无字媒体、来源、后处理参数、时长、尺寸、帧率、编码及封面帧。音轨/声音按任务意图决定，不默认自动发声。

## 可复用的效果记录

记录effect_id、目的/对象、trigger、from/to、duration/easing/order、interrupt/replay、reduced_motion、fallback、assets及verification。它是设计与执行记录，不是某个API的现成参数。

示例：产品角度预览由“查看细节”按钮触发，产品旋转到指定姿态，规格与购买入口保持静止；重复点击到当前目标姿态不叠加新时间轴，减少动态时直接切换静态角度图。真实交互产品可继续手动旋转；预渲染版只提供已有镜头选项并如实说明。

验证时至少覆盖代表性起/中/止帧、快速重复输入、中断返回、循环接缝、减少动态、媒体未加载和窄屏。实际目标设备/播放器录屏与状态记录优于只看开发预览。帧采样是有限证据，不宣称穷尽每一帧。
